# Дорожная карта проекта

> Tasker — простой таск-трекер с рабочими пространствами, канбан-доской и списком, задачами в нескольких проектах, документами пространства и интеграцией с GitHub.

## Этапы

- [x] **Каркас проекта** — Next.js + TypeScript, Tailwind + shadcn/ui, Prisma + PostgreSQL, docker-compose (Postgres, MinIO), логгер, единый формат ошибок, линтеры
- [x] **Аутентификация и глобальные роли** — Better Auth, регистрация и вход, роль администратора ресурса
- [x] **Рабочие пространства и доступы** — создание пространства, приглашения, участники, роли владельца и участника, общий слой проверки доступа
- [x] **Проекты и статусы** — проекты в пространстве, настраиваемые колонки-статусы
- [x] **Задачи** — срок, приоритет, ответственный, описание; размещение одной задачи в нескольких проектах со своим статусом в каждом
- [x] **Канбан-доска** — перетаскивание карточек между колонками и внутри колонки
- [x] **Представление списком** — таблица задач с фильтрами, сортировкой и пагинацией
- [x] **Комментарии к задачам** — обсуждение задачи участниками пространства
- [x] **Вложения** — загрузка файлов в S3/MinIO по временным ссылкам, ограничения по размеру и типу
- [x] **Профили и уведомления** — фото, должность и описание; публичный профиль и карточка участника; @упоминания в комментариях; уведомления в приложении и письмом с настройкой каналов
- [x] **Интерфейс и удобство** — редизайн каркаса, тёмная тема, панель задачи поверх доски и списков, перетаскивание статусов в настройках проекта
- [x] **Администрирование ресурса** — панель администратора для управления пользователями и пространствами
  - [x] Пользователи — список, блокировка, роли, завершение сессий, удаление (план `admin-users`)
  - [x] Пространства — список, архив и удаление, смена владельца, квота; доступ администратора — через имперсонацию (план `admin-resource`)
  - [x] Журнал действий — безопасность, пространства, содержимое, администрирование; видимость по категориям, лента в профиле участника, журнал безопасности, `/admin/activity`, срок хранения (план `admin-resource`)
  - [x] Карточка пользователя и имперсонация — сессии, токены, письма, ручное подтверждение email, вход «от имени» на час (план `admin-resource`)
  - [x] Обзор и настройки ресурса — счётчики, регистрации по дням, состояние, тестовое письмо; режим регистрации, домены email, квота по умолчанию (план `admin-resource`)
  - Аудит входов, режимы регистрации и 2FA-действия администратора из плана `admin-resource` переедут в IdP (этап «Единый вход (SSO) для tasker и meet»); в tasker остаются аудит пространств и содержимого, админка пространств, имперсонация
- [x] **Документы пространства** — своё хранилище с квотой, папки и теги, Markdown-заметки с редактором, просмотр файлов (картинки, PDF, текст, CSV, JSON, медиа), привязка документов к задачам (план `workspace-documents`)
- [x] **Интеграция с GitHub** — GitHub App, вебхуки, автоматическая привязка задач к PR, статус PR в задаче; ветки и коммиты, автосмена статуса, уведомления, вход через GitHub (план `github-integration`)
- [ ] **Готовность к продакшену** — Docker-образ, CI, e2e-тесты, аудит безопасности
  - [x] Docker-образ и CI — `Dockerfile` (`runner` + `migrate`), `compose.app.yml`, GitHub Actions (план `feature-docker-ci`, PR #1)
  - [ ] e2e-тесты — Playwright: регистрация → пространство → проект → задача → доска → комментарий с @упоминанием → приглашение; запуск в CI на чистом Postgres
  - [ ] аудит безопасности — фильтр по `workspaceId` во всех read-функциях и MCP-инструментах, presigned-ссылки, MIME при загрузке, рендер Markdown, подпись вебхуков
- [x] **Безопасность аутентификации** — недостающие сценарии Better Auth перед продакшеном (план `auth-security`)
  - [x] Сброс пароля по email (`sendResetPassword`)
  - [x] Подтверждение email при регистрации (`emailVerification`)
  - [x] Rate limit в хранилище `database` вместо `memory`
  - [x] Двухфакторная аутентификация (плагин `twoFactor`) и список активных сессий в профиле
- [ ] **Расширение задач** — функции, ожидаемые от таск-трекера (план `task-extensions`)
  - [x] История изменений задачи — статус, ответственный, срок и др., включая правки агентов через MCP
  - [x] Метки (labels) у задач
  - [x] Глобальный поиск и палитра Cmd+K — задачи по ключу и названию, документы, участники
  - [x] Архив вместо удаления — задачи, проекты, пространства (`archivedAt`)
  - [x] Наблюдатели задачи
  - [x] Напоминания о сроке и просрочке — планировщик (cron-контейнер или systemd-таймер)
  - [ ] Связи между задачами — «блокирует», «дублирует»
  - [ ] Массовые действия в списке — статус, ответственный, проект
- [ ] **Удобство работы** — скорость и обзор
  - [x] Обновления в реальном времени (SSE) для доски и комментариев (план `work-convenience`)
  - [x] Сохранённые фильтры списка и «Мои задачи» по всем пространствам
  - [x] Горячие клавиши на доске и в панели задачи
  - [x] Экспорт задач в CSV
  - [ ] Импорт из Trello / Jira
  - [x] Дашборд пространства — открытые и просроченные задачи, нагрузка по участникам
  - [x] Справка `/help` со сценариями и скриншотами (план `help-page`)
  - [x] Дизайн-система и айдентика — знак и фавикон, токены и тона, общие компоненты, UI-кит `/admin/design`, guard-тесты (план `design-system`)
- [ ] **Эксплуатация** — наблюдаемость и надёжность
  - [ ] Error tracking и метрики (Sentry / OpenTelemetry) поверх pino
  - [ ] Регулярная проверка восстановления из бэкапа — для дампов Postgres сделано в infra (вывоз в Object Storage, еженедельный `infra-backup-restore-check`); остаются файлы MinIO (`tasker-backup-files`)
  - [ ] Очистка «сиротских» объектов в S3 после удалений и неудачных загрузок
- [ ] **Переход на общую инфраструктуру** — сторона tasker; сама инфраструктура — в роадмапе `leha-creator/infra` (`D:\work\infra`)
  - [ ] Файлы в Yandex Object Storage — бакет `tasker-attachments` уже создан infra (свой сервисный аккаунт, CORS для `https://tracker.plwedding.ru`, lifecycle незавершённых загрузок), серверные проверки сделаны: чтение и запись из контейнера (MSS clamping), CORS preflight, presigned POST/GET, нет `X-Frame-Options`, задержка — `leha-creator/infra`, `docs/storage-handoff.md`. Осталось: скрипт ключа по образцу `rotate-yc-keys.sh` meet (ключ сразу в `/opt/tasker/.env`), браузерная загрузка 50 МБ на медленном канале при TTL 10 мин, `rclone sync`, новые `S3_*`, маршрут бакета убрать из `tracker.caddy`, затем удалить MinIO и `minio-init`; бэкап файлов (бакет без версионирования) — решить с владельцем
  - [ ] Общий PostgreSQL 18 — переезд с 17 через dump/restore, `pg_trgm`, сервис `postgres` убрать из `deploy/tasker/compose.yml`, бэкапы — из infra
  - [x] `deploy/edge` и bootstrap — общая часть сервера живёт в infra (`edge/`, `host/`); в tasker остался `deploy/bootstrap-app-server.sh` (только `/opt/tasker`, ключ деплоя, `.env`, таймеры; без сети `edge` и `/opt/edge/sites` останавливается), `tracker.caddy` делает `import access_log`, CI проверяет сниппет до загрузки (план `infra-edge-handoff`)
- [ ] **Единый вход (SSO)** — tasker как OIDC-клиент IdP `auth.plwedding.ru` (`genericOAuth`) с прежними локальными сессиями; сам IdP — в роадмапе `leha-creator/auth` (`D:\work\auth`). Регистрация свободная, своего допуска у tasker поверх IdP нет
  - [ ] Вход через IdP — локально остаются агенты (`isAgent`) и API-токены, роли пространств, глобальная роль admin, `UserProfile`, привязка GitHub-аккаунта для PR, имперсонация; имя, email и фото — из claims IdP; пароль, 2FA и сессии в `/profile/security` — ссылка на страницу аккаунта IdP
  - [ ] Журнал действий сохраняется — события `owner = identity` пишет IdP, tasker сливает их со своими в ленты (профиль «Безопасность», карточка пользователя, `/admin/activity`, обзор); операции админки над учётной записью идут в admin API IdP через прежний порт (см. «Совместимость с будущим IdP» в плане `admin-resource`)
  - [ ] Удалить из tasker перенесённое в IdP — формы входа и регистрации, сброс пароля, подтверждение email, 2FA, настройки регистрации
- [ ] **Связка tasker и meet** — после SSO, общий `sub` пользователя: созвон по задаче, конспект встречи в документы задачи; сервисные вызовы с подписанными вебхуками и токенами, без брокера (NATS JetStream — только если вебхуков перестанет хватать)
