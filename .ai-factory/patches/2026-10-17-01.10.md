# Создание пространства и проекта — панель справа вместо отдельных страниц

**Дата:** 2026-10-17 01:10
**Файлы:** src/components/layout/side-panel.tsx, src/components/layout/create-panel-href.ts (+ test), src/app/(app)/page.tsx, src/app/(app)/w/[workspaceSlug]/page.tsx, src/components/workspaces/workspace-list.tsx, src/components/workspaces/workspace-switcher-menu.tsx, src/components/projects/project-list.tsx, next.config.ts; удалены src/app/(app)/workspaces/new/page.tsx и src/app/(app)/w/[workspaceSlug]/projects/new/page.tsx
**Severity:** low

## Problem

«Создать пространство» и «Создать проект» уводили на отдельные страницы с карточкой формы. Нужно открывать форму панелью справа поверх списка (как панель задачи), с лёгким затемнением страницы и закрытием по клику на неё.

## Root Cause

Формы создания жили на отдельных маршрутах, а панель задачи (`TaskPanelFrame`) немодальная: она сужает страницу и не ловит клик снаружи, поэтому повторно использовать её для модальной панели нельзя.

## Solution

- `SidePanel` — модальная панель на примитивах radix `Dialog` (Portal + Overlay + Content): затемнение `bg-black/20` без размытия, тулбар `h-12` в стиле панели задачи, клик по затемнению и Esc закрывают её через `router.push(closeHref)`.
- Состояние панели — в адресе (`?create=workspace` на `/`, `?create=project` на `/w/[slug]`), по аналогии с `?task=`. Хелперы — в `create-panel-href.ts`.
- Панель проекта рендерится только при `manageProjects`; сервер всё равно проверяет право в action.
- Старые адреса `/workspaces/new` и `/w/:slug/projects/new` — редиректы в `next.config.ts`.
- После создания action делает `redirect()` на новую сущность, и панель исчезает вместе со сменой адреса.

## Prevention

- Для модальных панелей не использовать `SheetContent` из shadcn как есть: его overlay с `backdrop-blur` — не «лёгкое затемнение», а `ui/` вручную не правим. Собирать панель из примитивов radix.
- Открытые панели держать в search params, чтобы ссылки на них работали из любого места (например, из переключателя пространств).

## Дополнение: резкое закрытие

Закрытие выглядело как лаг: `onOpenChange` сразу делал `router.push`, панель ждала ответа сервера на новый адрес и пропадала без анимации. Теперь `SidePanel` держит `open` в своём состоянии: при закрытии сразу запускается анимация ухода (`data-[state=closed]:animate-out`, 200 мс), `router.push` — после неё (при `prefers-reduced-motion` — сразу), а `closeHref` заранее загружается через `router.prefetch`. Кнопка «Закрыть» — `Dialog.Close`, а не `Link`.

**Prevention:** модальное окно, привязанное к адресу, сначала закрывается локально (анимация), а адрес меняет потом — не связывать видимость с ответом сервера.
