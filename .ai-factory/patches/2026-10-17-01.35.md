# Иконки пространств и проектов, задачи по категориям на карточке проекта

**Дата:** 2026-10-17 01:35
**Файлы:** prisma/schema.prisma, prisma/migrations/20261016211906_add_entity_icons, src/shared/entity-icon/*, src/components/entity-icon/*, src/shared/access/workspace-access.ts (+ test), src/modules/workspaces/slices/workspace/*, src/modules/projects/{models/status-category.ts (+ test), slices/project/*}, src/components/workspaces/{workspace-list,workspace-switcher-menu,create-workspace-form,rename-workspace-form}.tsx, src/components/projects/{project-list,project-nav,create-project-form,project-settings-form}.tsx, src/components/layout/side-panel.tsx, страницы /w/[workspaceSlug], settings, projects/[projectId]/layout
**Severity:** low

## Problem

Пространства и проекты выглядели одинаково, без визуальных якорей. На карточке проекта показывалось число статусов — бесполезная цифра вместо полезной сводки по задачам.

## Root Cause

У Workspace и Project не было поля для иконки. Список проектов считал `_count.statuses`, хотя категории статусов (`todo` / `in_progress` / `done`) уже позволяли посчитать задачи по этапам.

## Solution

- Колонка `icon String?` у Workspace и Project. null — иконка не выбрана: `resolveEntityIcon` выбирает её стабильно по хешу id, поэтому старые записи сразу получили разные иконки без бэкфилла.
- Каталог из 10 ключей — в `shared/entity-icon` (иконки нужны модулям workspaces и projects, которые друг от друга не зависят). SVG (lucide) и цвет заливки — в `components/entity-icon`, у каждой иконки свой цвет.
- `icon` у Workspace не входит в схему плагина Better Auth: сервис пишет её репозиторием после `createOrganization` / `updateOrganization`, как `taskKey`. Ошибка записи при создании не роняет создание (лог `[workspace.icon] assign failed`).
- Выбор — радиокнопки-плитки (`EntityIconPicker`) в формах создания и настроек; Zod `z.enum(ENTITY_ICONS)`, пусто → не менять.
- Карточка проекта: `statuses { category, _count.placements }` → `countTasksByCategory` → «К выполнению / В работе / Готово».
- Попутно: `SidePanel` фокусирует первое поле формы, а не кнопку «Закрыть».

## Prevention

- Поля организации, которых нет в схеме Better Auth, писать репозиторием после вызова плагина и не делать обязательными в БД.
- Для «выбора из списка» с историческими данными — nullable-колонка и детерминированный фолбэк по id вместо одинакового значения по умолчанию.
- Bash-правки через `perl -0pi` с `|` в замене ломают TypeScript-юнионы (`string | null`): многострочные правки — через Edit.

- Карточка проекта: сводка вынесена в `CardContent` с линией `border-foreground/[0.06]` и отступом; категории строками, счётчик справа — `StatusCount` (фон цвета категории из палитры статусов, тёмный текст — читается в обеих темах).

**Prevention:** выравнивая иконку с многострочным заголовком, задавать явный `leading-*` строкам и подбирать размер плитки под их сумму, а не полагаться на line-height по умолчанию.

## Дополнение: сводка на карточке проекта

- Карточка вынесена в `components/projects/project-card.tsx`: в шапке — время последнего изменения; под линией — сегментная полоса прогресса («18% готово»), сетка 2×3: категории со счётчиками слева, «Просрочено» (красный счётчик только при > 0), «Мои задачи», «Всего задач» справа.
- Данные: `projectRepository.taskStatsByWorkspace` — один `$queryRaw` с `COUNT(*) FILTER` по всем проектам пространства (просроченные и мои открытые — статус в проекте не `done`, как у фильтра «Просрочено»; активность — `GREATEST(MAX(placement.updatedAt), MAX(task.updatedAt))`, фолбэк — `Project.updatedAt`). `completionPercent` — в `models/status-category`.
- `formatNotificationTime` из клиентского компонента уведомлений перенесён в `src/lib/format-relative-time.ts`: серверный компонент не может вызвать функцию из модуля `'use client'`.

**Prevention:** чистые форматтеры не держать в файлах `'use client'` — серверные компоненты получают оттуда только клиентские ссылки. Счётчики для списков — одним агрегирующим запросом на пространство, а не запросом на карточку.

## Дополнение: компактная карточка

Сетка 2×3 выглядела пусто, а тёмный текст на светлом цветном фоне — грязно. Теперь: полоса прогресса + одна строка (категории слева, «Просрочено» и «Мои» у правого края — только если не ноль; «Всего» убрано — видно по категориям). `StatusCount` — белое число на более тёмных тонах палитры (`COUNT_CLASSES`, контраст ≈ 4.5:1 в обеих темах), точки и сегменты остаются в светлых тонах (`DOT_CLASSES`). Две группы — два `<dl>` (div с группами внутри `<dl>` — невалидная разметка).

**Prevention:** для текста на цветной заливке брать отдельную, более тёмную палитру с белым текстом, а не подбирать цвет текста под светлые маркеры; нулевые «тревожные» счётчики не показывать.
