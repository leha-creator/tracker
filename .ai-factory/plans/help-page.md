## Settings
- Testing: yes, тесты только для логики. Vitest (`environment: node`, файлы `src/**/*.test.ts`):
  - каталог статей: уникальные `slug`, у каждой статьи есть файл;
  - каждая картинка из статей существует в `public/help-media/`;
  - каждая внутренняя ссылка `/help/<slug>` ведёт на статью из каталога;
  - оглавление собирается из заголовков с теми же `id`, что даёт `MarkdownView`;
  - `MarkdownView` пропускает картинки `/help-media/` только с явным префиксом.
  Скрипт скриншотов юнит-тестами не покрывается, его проверка — успешный прогон. Вёрстку страниц справки смотреть скриншотами Playwright на 1440 и 375 px.
- Logging: standard. В `src/` логировать только через `createLogger(scope)`, `console.*` запрещён. Уровни:
  - `debug` — чтение статьи (slug, размер);
  - `warn` — статья есть в каталоге, но файл не найден (страница отдаёт 404).
  Скрипт `scripts/help-screenshots/` пишет прогресс в консоль в стиле `scripts/run-reminders.mjs` (префикс `[help-screenshots]`): шаг засева, имя снятого файла и его размер, итог. Ошибки пишутся с именем шага и URL, после них выход с кодом 1. Пароли и токены демо-пользователей в лог не выводятся.
- Docs: yes. Обязательный docs-чекпоинт в конце (`/aif-docs`): `AGENTS.md`, `docs/development.md`, `docs/architecture.md`, `README.md`, `.ai-factory/ROADMAP.md`.

## Принятые решения (поправьте до `/aif-implement`, если не согласны)

1. **Справка — раздел приложения `/help`, доступный после входа.** Страницы лежат в `src/app/(app)/help/` и получают шапку, меню пользователя и Cmd+K. Публичной справку не делаем: `(app)/layout.tsx` требует сессию, и ради публичных страниц пришлось бы заводить отдельный каркас. Статьи о входе, регистрации и сбросе пароля тоже есть, их читают уже вошедшие пользователи или им пересылают ссылку. Если справка понадобится без входа, это отдельная задача.
2. **Охват: участник, владелец пространства, агенты и MCP.** Администрирование ресурса (`/admin`) не описываем. Там, где функция зависит от админа (режим регистрации, квота по умолчанию, подключение GitHub App), даём одну строку: «это настраивает администратор».
3. **Контент — Markdown-файлы в репозитории, `content/help/<slug>.md`.** Каталог статей (порядок, раздел, заголовок, краткое описание, аудитория) задаётся в TS: `src/modules/help/models/help-catalog.ts`. В Markdown только тело статьи, без frontmatter, новых зависимостей нет. Папку `docs/` не используем: `.dockerignore` исключает её из сборки.
   - Файлы читает серверная функция через `fs` и `path.join(process.cwd(), 'content/help')` с `'use cache'`.
   - Чтобы файлы попали в standalone-сборку, в `next.config.ts` добавляется `outputFileTracingIncludes: { '/help/**': ['./content/help/**'] }`. Задача 4 проверяет это по `.next/standalone`.
4. **Рендер — существующий `MarkdownView`.** Безопасность остаётся прежней: `skipHtml` и `safeMarkdownUrl`.
   - Сейчас картинки разрешены только с префиксами `/api/documents/` и `/api/attachments/`. Добавляется проп `imagePrefixes` (по умолчанию — прежний список), и справка передаёт `['/help-media/']`. Глобальный список не расширяем: пользовательские заметки не должны ссылаться на картинки справки.
   - Скриншоты лежат в `public/help-media/<article>/<name>.png`, а не в `public/help/`, чтобы статические файлы не пересекались с маршрутом `/help/[slug]`.
   - В Dockerfile добавляется `COPY --from=builder --chown=node:node /app/public ./public`. Комментарий в Dockerfile уже просит это сделать, а без строки в проде отдают 404 и `agent-avatar.svg`, и скриншоты.
5. **Страницы.**
   - `/help` — оглавление по разделам, у статей карточки с описанием и пометкой аудитории («Участник», «Владелец», «Агенты»).
   - `/help/[slug]` — слева навигация по всем статьям, в центре статья, справа на `xl` оглавление по `##`/`###`, внизу «Предыдущая / Следующая».
   - Статьи генерируются статически (`generateStaticParams`), для неизвестного slug — `notFound()`. Метаданные: `<Заголовок> — Справка Tasker`.
   - На мобильных навигация сворачивается в `<details>` над статьёй, без горизонтальной прокрутки на 375 px.
6. **Входы в справку.**
   - Пункт «Справка» в меню пользователя после «Горячие клавиши» (иконка `CircleHelpIcon`).
   - Ссылка «Подробнее в справке» в окне «Горячие клавиши».
   - Сочетание `g h` в группе «Переходы».
   - Команда «Справка» в палитре Cmd+K.
   - Глобальный поиск по статьям в Cmd+K в этот план не входит.
7. **Скриншоты снимает скрипт на Playwright: `pnpm help:screenshots`** (`node --env-file-if-exists=.env scripts/help-screenshots/run.mjs`). Скрипт написан на JavaScript (ESM), как остальные `scripts/*.mjs`. Модули приложения он не импортирует: в них `server-only` и алиасы `@/`.
   - Пакет `playwright` ставится в devDependencies с точной версией, браузер — разово через `pnpm exec playwright install chromium`.
   - **Целевой сервер** задаётся через `HELP_APP_URL` (по умолчанию `http://localhost:3000`). Требование: `AUTH_REQUIRE_EMAIL_VERIFICATION=false`, иначе скрипт останавливается с подсказкой.
   - **Нужна чистая база.** Если демо-пользователь `anna@help.example.com` уже есть, скрипт не засевает данные повторно и просит либо сбросить базу, либо запустить с флагом `--shots-only` (только съёмка по уже засеянным данным). Как поднять отдельную базу для справки, описано в `docs/development.md` (задача 14).
   - **Данные засеваются через UI и HTTP** — те же сценарии, что описаны в справке. SQL напрямую не используется, чтобы не обходить позиции, счётчики и журнал.
   - **Пользователи** создаются через `POST /api/auth/sign-up/email` (`autoSignIn`, cookie сохраняется в `storageState`). Их трое (Анна — владелец, Борис и Вера — участники), это укладывается в лимит 3 регистрации в минуту.
   - **Съёмка:**
     - светлая тема (`colorScheme: 'light'`), окно 1440×900, `deviceScaleFactor: 1`;
     - ждать конкретные элементы, а не `networkidle`: SSE держит соединение открытым;
     - перед снимком скрывать тосты Sonner;
     - токены и ключи 2FA закрывать опцией `mask`;
     - снимать либо всю видимую область, либо `locator.screenshot()` нужного блока.
   - **Не снимаем:** GitHub (нужна установленная GitHub App), письма, терминал Claude Code. Для них в статьях текст и блоки кода.
8. **Тексты пишутся по-русски, затем проходят скилл `humanizer:humanizer`** (задача 13). Правила для черновиков и правки:
   - обращение на «вы», короткие шаги нумерованным списком;
   - подписи интерфейса дословно в «ёлочках», как в коде компонентов;
   - без рекламных оборотов и общих вступлений;
   - в каждой статье: зачем это, пошаговые сценарии, ограничения и права («кто может»), что делать, если не получается;
   - humanizer меняет только формулировки. Факты, подписи UI, клавиши, лимиты, ссылки и пути к картинкам остаются прежними, после правки сверяются по `git diff`.

## Риски
- **`'use cache'` и `fs` в standalone.** Если `outputFileTracingIncludes` не сработает для маршрута с `cacheComponents`, запасной вариант — `COPY --from=builder /app/content ./content` в Dockerfile. Проверка в задаче 4 обязательна до коммита.

- **Лимиты Better Auth** (3 регистрации и 5 входов в минуту) на повторных прогонах. Пользователи входят один раз и переиспользуют `storageState`, при `--shots-only` повторного входа нет.
