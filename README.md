# Tasker

> Простой таск-трекер для команд: рабочие пространства, канбан-доска и список задач.

Tasker помогает командам вести задачи в изолированных рабочих пространствах. Одна задача может одновременно находиться в нескольких проектах, и в каждом у неё свой статус. Сейчас готовы каркас приложения, вход с глобальными ролями, рабочие пространства с приглашениями, проекты со статусами, задачи, канбан-доска с перетаскиванием карточек и список задач с фильтрами, а остальные возможности появляются по этапам [дорожной карты](.ai-factory/ROADMAP.md).

## Быстрый старт

Нужны Node.js 22+ (рекомендуется 24), Docker и corepack.

```bash
corepack enable
pnpm install
cp .env.example .env
pnpm infra:up      # Postgres (5433), MinIO (9000/9001), Mailpit (1025/8025)
pnpm db:deploy     # миграции БД
pnpm dev           # http://localhost:3000 → /register
```

Пользователь с email из `ADMIN_EMAILS` (по умолчанию `admin@example.com`) при регистрации становится администратором.

Проверка инфраструктуры:

```bash
curl http://localhost:3000/api/health
# {"status":"ok","checks":{"db":{"ok":true,...},"storage":{"ok":true,...}}}
```

## Что уже есть

- **Next.js 16 + TypeScript (strict)**: App Router, Server Components, Cache Components
- **Вход и регистрация**: Better Auth (email + пароль), глобальные роли `user` / `admin`, защищённые страницы
- **Администрирование ресурса**: список всех пользователей с поиском и фильтрами; блокировка с причиной и сроком, выдача и снятие роли администратора, завершение сессий, удаление (кроме единственных владельцев пространств)
- **Рабочие пространства**: создание, роли владельца и участника, приглашения по email со ссылкой (письма локально ловит Mailpit), единая проверка доступа `requireWorkspaceAccess()`
- **Проекты и статусы**: проекты в пространстве, настраиваемые колонки-статусы (категория, цвет, порядок), право «Управление проектами», которое владелец выдаёт участникам
- **Задачи**: ключ `TSK-42` (префикс задаёт пространство), приоритет, срок, ответственный; одна задача в нескольких проектах со своим статусом в каждом, быстрое создание в колонке
- **Канбан-доска**: перетаскивание карточек внутри колонки и между колонками (мышь, касание, клавиатура), оптимистичное обновление с откатом при ошибке
- **Список задач** в пространстве и в проекте: поиск, фильтры по проекту, статусу, приоритету, ответственному и сроку, сортировка, страницы; состояние в URL
- **Комментарии к задачам**: обсуждение на странице задачи; править может автор, удалять — автор или владелец пространства; @упоминания с подсказкой участников
- **Профили**: фото, должность, описание; публичный профиль участника со статистикой задач и карточка при наведении
- **Уведомления**: колокольчик и страница уведомлений, письма; упоминания, назначения, комментарии к моим задачам, приглашения; каналы настраиваются в профиле
- **Вложения**: файлы до 25 МБ к задаче и комментариям, загрузка из браузера прямо в S3/MinIO по временным ссылкам, миниатюры картинок, проверка типа и содержимого
- **Документы пространства**: своё хранилище с квотой, папки и теги, Markdown-заметки с редактором и безопасным рендером, просмотр картинок, PDF, текста, CSV, JSON, аудио и видео; привязка документов к задачам; право «Управление документами»
- **Интеграция с GitHub** (необязательно): GitHub App, вход через GitHub; PR, ветки и коммиты с `TSK-42` в названии привязываются к задаче, статус PR, ревью и CI видны в задаче и на доске, проект сам двигает задачу при открытии и слиянии PR — [подробнее](docs/github.md)
- **Tailwind CSS v4 + shadcn/ui**: готовые компоненты в `src/components/ui`
- **PostgreSQL + Prisma 7**: driver adapter `@prisma/adapter-pg`, логирование SQL-запросов
- **S3-хранилище**: MinIO локально, `@aws-sdk/client-s3` и presigned POST/GET, приватный бакет
- **Структурированные логи**: pino, уровень через `LOG_LEVEL`, секреты скрываются автоматически
- **Единый формат ошибок**: `{ code, message, fieldErrors? }` для Server Actions и API
- **Контроль качества**: ESLint с правилами архитектурных границ, Prettier, Vitest, pre-commit хук
- **Docker и CI**: standalone-образ с отдельным контейнером миграций, GitHub Actions (проверки, миграции на чистой БД, smoke-тест образа)

## Пример: Server Action в едином формате

```ts
'use server';

import { createLogger } from '@/shared/logger';
import { NotFoundError, ok, toActionError, type ActionResult } from '@/shared/errors';

const log = createLogger('tasks');

export async function archiveTaskAction(taskId: string): Promise<ActionResult<null>> {
  try {
    log.debug({ taskId }, '[archiveTaskAction] start');
    const task = await findTask(taskId);
    if (!task) throw new NotFoundError('Задача не найдена');
    // ...
    return ok(null);
  } catch (error) {
    // Клиент получит { ok: false, error: { code: 'NOT_FOUND', message: 'Задача не найдена' } }
    return toActionError(error, { action: 'archiveTask', taskId });
  }
}
```

## Основные команды

| Команда | Что делает |
|---------|------------|
| `pnpm dev` | Dev-сервер |
| `pnpm check` | typecheck + lint + format:check + тесты |
| `pnpm build` | Production-сборка |
| `pnpm infra:up` / `pnpm infra:down` | Поднять / остановить Postgres, MinIO и Mailpit |
| `pnpm db:migrate` | Создать и применить миграцию Prisma |
| `pnpm app:up` / `pnpm app:down` | Запустить приложение с миграциями и инфраструктурой в Docker (http://localhost:3001) / остановить |

Полный список команд описан в [docs/development.md](docs/development.md).
