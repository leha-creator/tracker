Tasker работает как MCP-сервер: Claude Code в любом репозитории читает задачи и документы пространства, создаёт задачи, меняет статусы, пишет комментарии и прикладывает файлы. Ставить ничего не нужно: Claude Code подключается по адресу Tasker с токеном доступа.

## Что нужно

- Claude Code на компьютере, где лежит репозиторий.
- Токен доступа: токен агента пространства или личный токен. Как их выпустить и чем они отличаются, описано в статье [Агенты и токены доступа](/help/agents-and-tokens).

Токен действует в одном пространстве. Если вы работаете с несколькими пространствами, нужен отдельный токен для каждого.

## Подключить Claude Code

После выпуска токена Tasker показывает окно с тремя блоками: сам токен, команда для Claude Code и файл `.mcp.json`. У каждого блока есть кнопка «Скопировать».

![Окно созданного токена с командами подключения](/help-media/claude-code-mcp/connect.png "Токен «Claude Code — ноутбук» создан: токен, команда claude mcp add и .mcp.json")

Скопируйте токен сразу: после кнопки «Готово» Tasker его больше не покажет.

### Команда для одного репозитория

1. Скопируйте команду из блока «Подключить Claude Code (выполнить в папке репозитория)».
2. Выполните её в папке репозитория:

```bash
claude mcp add --transport http --scope local tasker https://tasker.example.com/api/mcp --header "Authorization: Bearer tkr_…"
```

С `--scope local` сервер и токен сохраняются в локальных настройках Claude Code только для этого репозитория и только у вас. В git они не попадают.

### Файл `.mcp.json` для команды

Если подключение нужно всем, кто работает с репозиторием, положите в его корень файл `.mcp.json` из блока «Или .mcp.json в корне репозитория»:

```json
{
  "mcpServers": {
    "tasker": {
      "type": "http",
      "url": "https://tasker.example.com/api/mcp",
      "headers": {
        "Authorization": "Bearer ${TASKER_TOKEN}"
      }
    }
  }
}
```

Токена в файле нет: Claude Code берёт его из переменной окружения `TASKER_TOKEN`. Каждый участник задаёт свой токен у себя, например в профиле shell:

```bash
export TASKER_TOKEN="tkr_…"
```

При первом запуске Claude Code спросит, разрешить ли сервер из `.mcp.json`.

### Проверить подключение

Запустите Claude Code в папке репозитория и выполните команду `/mcp`. Сервер `tasker` должен быть в состоянии `connected`.

## Области токена и инструменты

Инструменты, на которые у токена нет области, Tasker не показывает агенту и не даёт вызвать. Области задаются при выпуске токена, подробнее — в разделе [Области токена](/help/agents-and-tokens#области-токена).

Область не заменяет права. Например, для `create_note` нужны и область `documents`, и право «Управление документами» у владельца токена.

### Чтение (`read`)

Эта область есть у любого токена.

| Инструмент | Что делает |
|------------|------------|
| `get_workspace_context` | От чьего имени работает агент и какие у него области, проекты со статусами, участники, метки, правила документов и GitHub. Агент вызывает его первым |
| `list_tasks` | Поиск задач по тексту или ключу и фильтры: проект, статус, ответственный, приоритет, метки, срок |
| `get_task` | Задача целиком: поля, статусы в проектах, родитель и подзадачи, PR, ветки и коммиты, последние комментарии, связанные документы, рекомендованное имя ветки |
| `get_task_history` | История изменений задачи с автором |
| `get_attachment_url` | Временная ссылка на файл, прикреплённый к задаче или комментарию |
| `get_github_conventions` | Правила привязки к GitHub, подключённые репозитории и автосмена статуса по проектам |
| `preview_github_links` | Какие задачи привяжет имя ветки, текст коммита или PR |
| `list_documents` | Документы папки или поиск по всему разделу «Документы» |
| `list_document_folders` | Дерево папок документов |
| `list_document_tags` | Теги документов пространства |
| `get_document` | Текст заметки или текстового файла, ссылка на остальные файлы, связанные задачи |

### Задачи (`tasks`)

| Инструмент | Что делает |
|------------|------------|
| `create_task` | Создать задачу или подзадачу |
| `update_task` | Изменить название, описание, приоритет, срок, ответственного, метки |
| `set_task_status` | Поставить статус задачи в проекте |
| `set_task_parent` | Сделать задачу подзадачей другой или вернуть на верхний уровень |
| `archive_task` | Убрать задачу в архив вместе с подзадачами |
| `restore_task` | Вернуть задачу из архива |
| `add_comment` | Написать комментарий, упомянуть участников через `@Имя`, приложить файлы |
| `request_attachment_upload` | Шаг 1 загрузки файла в задачу или комментарий: получить готовую команду `curl` |
| `complete_attachment_upload` | Шаг 2: подтвердить загрузку после `curl` |

### Документы (`documents`)

| Инструмент | Что делает |
|------------|------------|
| `create_note` | Создать заметку в папке, с тегами и связями с задачами |
| `update_note` | Изменить название или текст заметки. Если заметку изменили после чтения, вызов отклоняется |
| `create_document_folder` | Создать папку |
| `set_document_tags` | Заменить теги документа существующими тегами |
| `link_document_to_task` | Связать документ с задачей |
| `unlink_document_from_task` | Убрать связь документа с задачей |
| `request_document_upload` | Шаг 1 загрузки файла в «Документы» |
| `complete_document_upload` | Шаг 2: подтвердить загрузку |

Агент не удаляет задачи, вложения, документы и папки и не создаёт новые теги документов.

## Сценарии start_task и finish_task

Tasker даёт Claude Code два готовых сценария. В Claude Code это слэш-команды, которым передают ключ задачи. Для них нужна область `tasks`.

`/mcp__tasker__start_task SEV-42` начинает работу над задачей. Агент:

1. Читает задачу через `get_task`: описание, комментарии, связанные документы, уже привязанные PR и ветки.
2. Читает связанные документы, а если их нет, ищет документы по теме.
3. Если задача большая, разбивает её на подзадачи и ведёт каждую в своей ветке.
4. Переводит задачу в статус «в работе». Если в проекте настроена автосмена статуса при открытии PR, статус не трогает.
5. Создаёт ветку с ключом задачи, например `sev-42-ispravit-vkhod`.
6. Начинает каждый коммит с `SEV-42: ` и не упоминает ключи других задач.
7. Пишет в задачу короткие комментарии о важных решениях, блокерах и вопросах.

`/mcp__tasker__finish_task SEV-42` завершает работу. Агент:

1. Проверяет, что изменения закоммичены и отправлены.
2. Готовит заголовок PR `SEV-42: …` и проверяет через `preview_github_links`, что он привяжется ровно к `SEV-42`.
3. Открывает PR.
4. Пишет в задачу итоговый комментарий: что сделано, что осталось, ссылка на PR.
5. Если у токена есть область `documents`, сохраняет решения и инструкции заметкой, связанной с задачей.
6. Ставит статус. Если в проекте настроена автосмена статуса при слиянии PR, оставляет статус Tasker. Иначе ставит «готово», когда работа слита или не требует ревью.

## Пример: от задачи до PR

Начните задачу:

```text
/mcp__tasker__start_task SEV-42
```

Агент создаст ветку и будет коммитить с ключом задачи:

```bash
git switch -c sev-42-ispravit-vkhod
git commit -m "SEV-42: проверять срок действия ссылки сброса пароля"
```

Когда работа готова, завершите задачу:

```text
/mcp__tasker__finish_task SEV-42
```

Агент откроет PR и оставит комментарий в задаче:

```bash
gh pr create --title "SEV-42: исправить вход по ссылке сброса" --body "Проверка срока ссылки и тест"
```

Ветка, коммиты и PR появятся в разделе «GitHub» задачи `SEV-42`, если репозиторий подключён к пространству. Подробнее — в статье [GitHub](/help/github).

## Правила GitHub для агента

Агент получает правила привязки при подключении, а полностью — через `get_workspace_context` и `get_github_conventions`. Главное:

- Одна задача — одна ветка. Имя ветки начинается с ключа: `sev-42-…`. Рекомендованное имя отдаёт `get_task`.
- Каждый коммит начинается с `SEV-42:`, заголовок PR — `SEV-42: …`.
- В заголовке и описании PR нет ключей других задач, даже родительской: каждый ключ привязывает PR к своей задаче.
- У подзадачи свой ключ, и работа над ней идёт в ветке с её ключом.
- Если в проекте настроена автосмена статуса по PR, агент не двигает статус вручную.
- Перед `git push` и `gh pr create` агент проверяет текст через `preview_github_links`.

Чтобы агент следовал этим правилам и без сценариев, добавьте их в `CLAUDE.md` репозитория.

## Если что-то не получается

**`/mcp` показывает `failed` или `needs authentication`.** Токен неверный, отозван или истёк, вас удалили из пространства или агента отключили. Выпустите новый токен и подключите сервер заново.

**Сервер из `.mcp.json` не подключается.** Переменная `TASKER_TOKEN` не задана в окружении, где запущен Claude Code.

**Агент не видит `create_task` или `create_note`.** У токена нет области `tasks` или `documents`. Области не меняются: выпустите новый токен с нужной областью.

**«Недостаточно прав для управления документами».** У агента или у владельца личного токена нет права «Управление документами». Его выдаёт владелец пространства.

**Слэш-команд `start_task` и `finish_task` нет.** У токена нет области `tasks`.

**«Задача … не из этого пространства».** Токен выпущен для другого пространства: у каждого пространства свой ключ задач.

**«Укажите project» при смене статуса.** Задача лежит в нескольких проектах или ни в одном. Назовите агенту проект.

**PR не привязался к задаче.** Ключ стоит не отдельным словом, репозиторий не подключён к пространству или к Tasker не подключено приложение GitHub. Последнее настраивает администратор.

**`curl` при загрузке файла не может подключиться к хранилищу.** Хранилище файлов Tasker недоступно с компьютера, где работает агент. Это настраивает администратор.

**Токен перестал работать после архивации пространства.** В архивном пространстве токены не работают, пока владелец не восстановит пространство.
