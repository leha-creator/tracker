Tasker связывает задачи с работой в GitHub. Если ключ задачи, например `SEV-42`, есть в имени ветки, в заголовке PR или в тексте коммита, ветка, PR и коммит появляются в задаче, а состояние PR видно на доске и в списке.

Интеграция работает, только если к Tasker подключено приложение GitHub (GitHub App). Это настраивает администратор. Пока приложения нет, в настройках пространства на странице «GitHub» написано «GitHub ещё не подключён к Tasker», а раздела GitHub в задачах нет.

## Ключ задачи

У каждого пространства свой ключ задач: в «Студии Север» это `SEV`, поэтому задачи называются `SEV-1`, `SEV-42` и так далее. Ключ задаёт владелец в настройках пространства, в разделе «Ключ задач».

Tasker находит ключ в таких местах:

| Где написан ключ | Что привяжется к задаче |
|------------------|-------------------------|
| Имя ветки PR, заголовок или описание PR | PR |
| Имя ветки, в которую отправили коммиты | Ветка и все коммиты из этой отправки |
| Текст коммита | Только этот коммит |

Правила распознавания:

- Регистр не важен: подходят `sev-42-login`, `feature/SEV-42`, `[SEV-42]`, `SEV-42: исправить вход`.
- Ключ должен стоять отдельным словом. `SEV-042`, `SEV-42abc` и `2SEV-42` не распознаются.
- Ключ должен совпадать с ключом пространства, к которому подключён репозиторий.
- Если ключ убрать из заголовка или описания PR, автоматическая связь пропадёт.
- Если владелец сменит ключ, ветки и PR со старым ключом перестанут распознаваться. Уже созданные связи останутся.

## Привязать свой GitHub-аккаунт

Аккаунт GitHub нужен для входа через GitHub, для уведомлений о ревью ваших PR, а владельцу пространства ещё и для подключения репозиториев.

1. Откройте профиль, вкладку «Аккаунт».
2. В разделе «GitHub» нажмите «Привязать GitHub».
3. Разрешите доступ на странице GitHub. Tasker вернёт вас в профиль.

Чтобы убрать привязку, нажмите «Отвязать» в том же разделе.

Вход в Tasker — только через plwedding ID, см. [Регистрация и вход](/help/getting-started). Привязанный GitHub нужен для работы с репозиториями и уведомлений о PR.

## Подключить репозитории к пространству

Подключать репозитории может только владелец пространства с привязанным аккаунтом GitHub.

1. Откройте «Настройки» пространства и в разделе «GitHub» нажмите «Подключить репозитории».
2. В блоке «Добавить установку» нажмите «Установить GitHub App».
3. На GitHub выберите личный аккаунт или организацию и репозитории, к которым приложение получит доступ.
4. GitHub вернёт вас в Tasker с сообщением «Установка подключена».
5. В блоке «Подключённые установки» включите переключатель у каждого репозитория, который нужен пространству.

События приходят только из включённых репозиториев. Если приложение уже установлено на аккаунт, повторно ставить его не нужно: оно появится в блоке «Добавить установку» с кнопкой «Подключить».

Список репозиториев, к которым у приложения есть доступ, меняется на GitHub по ссылке «Доступ на GitHub».

Если выключить репозиторий, из задач пространства пропадут его PR, ветки и коммиты. Кнопка «Отключить» у установки делает то же самое для всех её репозиториев, а само приложение остаётся установленным на GitHub.

## Раздел GitHub в задаче

Здесь собраны PR, ветки и коммиты задачи:

- У PR видны заголовок со ссылкой на GitHub, репозиторий и номер, состояние («Открыт», «Черновик», «Слит», «Закрыт»), итог ревью («Одобрен», «Нужны изменения»), состояние CI («CI выполняется», «CI пройден», «CI упал») и автор.
- Ветки показаны с именем репозитория. Удалённая ветка зачёркнута и помечена «удалена».
- Коммиты показаны с коротким хешем, текстом, автором и временем. Видны последние, остальные сведены в строку «и ещё N».

### Имя ветки

Пока к задаче ничего не привязано, раздел подсказывает имя ветки: ключ задачи и название латиницей, например `sev-42-ispravit-vkhod`. Кнопка «Скопировать имя ветки» копирует его в буфер.

### Привязать PR вручную

Если ключа в PR нет, привяжите PR по ссылке:

1. Вставьте в поле внизу раздела ссылку вида `https://github.com/owner/repo/pull/12`.
2. Нажмите «Привязать».

Привязать PR вручную может любой участник пространства. Репозиторий PR должен быть включён в настройках GitHub пространства.

### Отвязать PR

Нажмите на значок «Отвязать» справа от PR. После этого PR не привяжется к задаче снова, даже если ключ задачи останется в его тексте. Вернуть связь можно ручной привязкой.

## Индикатор PR на доске и в списке

На карточке доски и в строке списка задач показывается значок PR. Если у задачи несколько PR, рядом стоит их число, а значок показывает самое заметное состояние: открытый PR важнее черновика, черновик — слитого, слитый — закрытого.

## Автосмена статуса

Проект может сам переводить задачу в другой статус по событиям PR. Настроить это может участник с правом «Управление проектами».

1. Откройте проект и вкладку «Настройки».
2. В разделе «GitHub» выберите статусы в полях «Когда PR открыт или готов к ревью» и «Когда PR слит». Вариант «Не менять» отключает смену статуса для этого события.
3. Нажмите «Сохранить».

Правила автосмены:

- Статус меняется только вперёд по категориям: «К выполнению» → «В работе» → «Готово». Задачу из категории «Готово» повторно открытый PR не вернёт в работу.
- Черновик PR и закрытие PR без слияния статус не меняют.
- Если задача лежит в нескольких проектах, статус меняется в каждом по его собственной настройке.
- Если к задаче привязали уже открытый или слитый PR, сразу применяется настройка для его текущего состояния.
- Если выбранный статус удалить из проекта, настройка сбрасывается на «Не менять».

## Уведомления о PR

В профиле на вкладке «Уведомления» есть три типа уведомлений про PR:

| Тип | Кому приходит | Письмо по умолчанию |
|-----|---------------|---------------------|
| «PR к моим задачам» | Ответственному за задачу, к которой привязали PR | нет |
| «Слияние PR» | Ответственному за задачу, PR которой слит | нет |
| «Ревью моих PR» | Автору PR, когда PR одобрили или запросили изменения | да |

«Ревью моих PR» приходит, только если ваш аккаунт GitHub привязан к профилю и вы участник пространства. О собственных действиях уведомления не приходят. Как включать и выключать каналы, описано в статье [Профиль и уведомления](/help/profile-and-notifications).

## Если что-то не получается

**В настройках написано «GitHub ещё не подключён к Tasker».** Администратор ещё не подключил приложение GitHub к Tasker. Обратитесь к нему.

**Кнопка «Установить GitHub App» неактивна, рядом блок «Привяжите GitHub».** Привяжите аккаунт GitHub в профиле, на вкладке «Аккаунт».

**Страница «GitHub» в настройках пространства не открывается.** Её видит только владелец пространства.

**После установки появилось сообщение «Ссылка установки устарела или открыта другим пользователем».** Ссылка установки живёт 10 минут. Начните подключение заново.

**«Эта установка GitHub App вам недоступна».** Вы вошли на GitHub под другим аккаунтом. Войдите в аккаунт, привязанный к профилю Tasker, и повторите.

**PR, ветка или коммит не привязались.** Проверьте три вещи: репозиторий включён в настройках GitHub пространства; ключ совпадает с ключом пространства; ключ стоит отдельным словом и без ведущего нуля.

**PR привязался к лишней задаче.** В заголовке или описании PR есть ключ этой задачи. Уберите его и сохраните PR, связь пропадёт. Или нажмите «Отвязать» в задаче.

**Не приходят уведомления о ревью.** Привяжите GitHub в профиле и проверьте, что тип «Ревью моих PR» включён на вкладке «Уведомления».

**Вместо логина GitHub в профиле написано «логин недоступен».** Доступ к GitHub истёк. Нажмите «Отвязать», затем «Привязать GitHub» снова.

**В проекте нет раздела «GitHub» в настройках.** Нужно право «Управление проектами». Если оно есть, значит, приложение GitHub не подключено к Tasker.
