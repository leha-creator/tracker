# Claude Code и MCP

Tasker работает как MCP-сервер. Агент Claude Code в любом репозитории может:

- смотреть задачи пространства;
- создавать задачи и подзадачи;
- менять статусы и писать комментарии.

Агент знает правила привязки к GitHub. Он сам называет ветку по ключу задачи (`tsk-42-…`), пишет ключ в коммитах и заголовке PR, и Tasker связывает задачу с веткой и PR.

Ставить ничего не нужно. Claude Code подключается к адресу `<BETTER_AUTH_URL>/api/mcp` с личным токеном.

## Быстрый старт

1. В Tasker откройте **Профиль → Токены доступа** (`/profile/tokens`) и нажмите **Создать токен**.
2. Укажите название (например, «Claude Code — backend»), пространство и срок действия.
3. Скопируйте токен: он показывается один раз.
4. В папке репозитория выполните команду из диалога:

   ```bash
   claude mcp add --transport http --scope local tasker https://tracker.plwedding.ru/api/mcp \
     --header "Authorization: Bearer tkr_…"
   ```

   `--scope local` сохраняет сервер и токен в локальных настройках Claude Code только для этого репозитория, вне git.

5. Проверьте подключение: в Claude Code выполните `/mcp`. Сервер `tasker` должен быть `connected`.
6. Добавьте в `CLAUDE.md` репозитория блок из [`docs/agents/CLAUDE.snippet.md`](agents/CLAUDE.snippet.md). Он говорит агенту вести задачи в Tasker и соблюдать правила ключей.

### Вариант для команды: `.mcp.json`

Если подключение должно быть у всех, кто работает с репозиторием, положите в его корень `.mcp.json` ([пример](agents/mcp.json.example)). Токен берётся из переменной окружения `TASKER_TOKEN` и в репозиторий не попадает:

```json
{
  "mcpServers": {
    "tasker": {
      "type": "http",
      "url": "https://tracker.plwedding.ru/api/mcp",
      "headers": { "Authorization": "Bearer ${TASKER_TOKEN}" }
    }
  }
}
```

Каждый участник выпускает свой токен и задаёт `TASKER_TOKEN` в окружении: в профиле shell или через `direnv`. Claude Code спросит разрешение на сервер из `.mcp.json` при первом запуске.

## Токены доступа

| Свойство | Как работает |
|----------|--------------|
| Права | Права владельца токена в **одном** пространстве. Участник с токеном может то же, что участник в интерфейсе |
| Админка | Не даёт никогда: сессия токена всегда с ролью `user` |
| Хранение | В БД — только SHA-256 и начало токена (`tkr_abcd1234`) для списка. Сам токен показывается один раз |
| Срок | 30, 90 дней, год или бессрочно |
| Отзыв | **Отозвать** в списке — доступ пропадает сразу. Вернуть токен нельзя, только выпустить новый |
| Лимит | 20 действующих токенов на пользователя |
| Блокировка и выход | Если пользователя заблокировали или он вышел из пространства, токен сразу перестаёт работать. Удаление пространства удаляет его токены |
| Последнее использование | Видно в списке, обновляется не чаще раза в минуту |

Храните токен как пароль: не коммитьте его и не вставляйте в задачи и PR.

## Что умеет агент

### Инструменты

| Инструмент | Что делает |
|------------|------------|
| `get_workspace_context` | Проекты со статусами (id, названия, категории), участники (для ответственного и `@`-упоминаний) и правила GitHub. Агент вызывает его первым |
| `list_tasks` | Поиск и фильтры: текст или ключ, проект, статус или категория (`todo`, `in_progress`, `done`, `none`), ответственный (`me`, `none`, email, имя), приоритет, срок, «только верхнего уровня», сортировка, страницы по 50 |
| `get_task` | Задача целиком: поля, статусы в проектах, цепочка родителей, подзадачи с прогрессом, PR (состояние, ревью, CI), ветки, коммиты, последние комментарии, рекомендованное имя ветки |
| `create_task` | Новая задача или подзадача (`parent`). Без `project` задача верхнего уровня встаёт в единственный проект пространства, если он один. Подзадача без `project` на доску не выводится — как в интерфейсе |
| `update_task` | Название, описание, приоритет, срок, ответственный. `null` очищает поле |
| `set_task_status` | Статус по названию, id или категории. Если задачи нет в проекте, она туда добавляется. `project` нужен, когда задача в нескольких проектах или ни в одном |
| `set_task_parent` | Сделать задачу подзадачей другой или вернуть на верхний уровень (`parent: null`). Циклы и вложенность глубже 10 уровней отклоняются |
| `add_comment` | Комментарий простым текстом. `@Имя` упоминает участника, и он получает уведомление |
| `get_github_conventions` | Правила привязки, подключённые репозитории и автосмена статуса по проектам |
| `preview_github_links` | Какие задачи привяжет имя ветки, сообщение коммита или текст PR. Тот же разбор, что у вебхука. С `repository` проверяет, что репозиторий подключён |

Задачи указываются как `TSK-42`, `tsk-42`, `#42` или `42`. Ключ другого пространства отклоняется с подсказкой правильного. Ошибки (нет прав, неизвестный статус, цикл подзадач) приходят агенту текстом, и он может исправить вызов.

### Сценарии (промпты)

В Claude Code они доступны как слэш-команды:

| Команда | Что делает агент |
|---------|------------------|
| `/mcp__tasker__start_task TSK-42` | Читает задачу. Большую разбивает на подзадачи. Переводит задачу «в работу», если её не двинет автосмена. Создаёт ветку `tsk-42-…` и коммитит с `TSK-42:` |
| `/mcp__tasker__finish_task TSK-42` | Проверяет заголовок PR через `preview_github_links`, открывает PR `TSK-42: …`, оставляет комментарий-итог со ссылкой на PR, ставит статус по правилам автосмены |

## Как агент работает с GitHub

Правила те же, что в [Интеграции с GitHub](github.md#что-привязывается). Агент получает их тремя путями:

1. **При подключении:** в инструкциях MCP-сервера — коротко.
2. **Через `get_github_conventions` и `get_workspace_context`:** полностью, с подключёнными репозиториями и автосменой статуса.
3. **Через `preview_github_links`:** проверка конкретной ветки или PR перед `git push` и `gh pr create`.

Главное:

- Одна задача — одна ветка: `tsk-42-short-slug`. Рекомендованное имя отдаёт `get_task`.
- Каждый коммит начинается с `TSK-42:`, заголовок PR — `TSK-42: …`.
- В PR **не упоминаются ключи других задач**, даже родительской: каждый ключ привязывает PR к своей задаче.
- У подзадачи свой ключ, работа над ней идёт в ветке с её ключом.
- Если в проекте настроена автосмена статуса по PR, агент не двигает статус вручную на этих шагах. Иначе ставит `in_progress` при старте и `done` после слияния.
- Если репозиторий не выбран в настройках GitHub пространства, привязки не будет, и агент сообщает об этом пользователю.

## Ограничения

- Агент не удаляет задачи и не работает с вложениями и документами.
- Действия агента в интерфейсе выглядят как действия владельца токена. Отдельной отметки «сделано агентом» нет: токены различаются только в логах (`tokenId`).
- Частота запросов по токену не ограничивается.
- Авторизация MCP — только bearer-токен, без OAuth.

## Частые проблемы

| Симптом | Причина |
|---------|---------|
| `/mcp` показывает `failed` или `needs authentication` | Токен неверный, отозван или истёк, пользователь заблокирован или вышел из пространства. Выпустите новый токен и переподключите сервер |
| В `.mcp.json` сервер не подключается | Переменная `TASKER_TOKEN` не задана в окружении, где запущен Claude Code |
| «Задача ABC-1 не из этого пространства» | Токен выпущен для другого пространства: у каждого пространства свой ключ |
| «Укажите project» в `set_task_status` | Задача в нескольких проектах или ни в одном (частый случай для подзадач) |
| PR не привязался к задаче | Ключ не на границе слова или с ведущим нулём, репозиторий не выбран в пространстве, GitHub App не создан. Проверьте текст через `preview_github_links` с `repository` |
| PR привязался к лишней задаче | В заголовке или описании PR есть её ключ. Уберите его и сохраните PR: связи пересчитаются |
