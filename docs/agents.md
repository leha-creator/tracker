# Claude Code и MCP

Tasker работает как MCP-сервер. Агент Claude Code в любом репозитории может:

- смотреть задачи пространства;
- создавать задачи и подзадачи;
- менять статусы и писать комментарии;
- прикреплять файлы (логи, скриншоты, отчёты) и читать файлы, которые прикрепили люди;
- читать документы пространства (спецификации, ADR), писать заметки и загружать файлы в «Документы».

Агент знает правила привязки к GitHub. Он сам называет ветку по ключу задачи (`tsk-42-…`), пишет ключ в коммитах и заголовке PR, и Tasker связывает задачу с веткой и PR.

Ставить ничего не нужно. Claude Code подключается к адресу `<BETTER_AUTH_URL>/api/mcp` с токеном доступа. Токен бывает двух видов:

| | Токен агента | Личный токен |
|---|---|---|
| От чьего имени | Агента пространства — отдельного участника («Claude — backend») | Пользователя, выпустившего токен |
| Кто выпускает | Владелец пространства, в **Настройки → Агенты** | Сам пользователь, в **Профиль → Токены доступа** |
| Автор задач, комментариев, документов | Агент (робот вместо фото, метка «Агент») | Пользователь, с пометкой «через Claude Code» |
| Права | Права агента: участник + «Управление проектами» / «Управление документами», если выданы | Права пользователя |
| Уведомления агенту | Получает ответственный за агента | — |

Токен агента удобен, когда агент работает сам по себе (по агенту на репозиторий): в истории видно, что сделал агент, а права и токены не зависят от того, кто их выпустил. Личный токен — когда человек работает в паре с Claude Code на своей машине.

## Быстрый старт

1. Выпустите токен:
   - **токен агента:** **Настройки пространства → Агенты** (`/w/<slug>/settings/agents`) → **Создать агента**, затем откройте агента и нажмите **Создать токен**;
   - **личный токен:** **Профиль → Токены доступа** (`/profile/tokens`) → **Создать токен**.
2. Укажите название (например, «Ноутбук Анны»), срок действия и области (см. [Области токена](#области-токена)).
3. Скопируйте токен: он показывается один раз.
4. В папке репозитория выполните команду из диалога:

   ```bash
   claude mcp add --transport http --scope local tasker https://tracker.plwedding.ru/api/mcp \
     --header "Authorization: Bearer tkr_…"
   ```

   `--scope local` сохраняет сервер и токен в локальных настройках Claude Code только для этого репозитория, вне git.

5. Проверьте подключение: в Claude Code выполните `/mcp`. Сервер `tasker` должен быть `connected`.
6. Добавьте в `CLAUDE.md` репозитория блок из [`docs/agents/CLAUDE.snippet.md`](agents/CLAUDE.snippet.md). Он говорит агенту вести задачи в Tasker, читать и писать документы и соблюдать правила ключей.

### Вариант для команды: `.mcp.json`

Если подключение должно быть у всех, кто работает с репозиторием, положите в его корень `.mcp.json` ([пример](agents/mcp.json.example)). Токен берётся из переменной окружения `TASKER_TOKEN` и в репозиторий не попадает:

```json
{
  "mcpServers": {
    "tasker": {
      "type": "http",
      "url": "https://tracker.plwedding.ru/api/mcp",
      "headers": { "Authorization": "Bearer ${TASKER_TOKEN}" }
    }
  }
}
```

Каждый участник задаёт `TASKER_TOKEN` в окружении: в профиле shell или через `direnv`. Claude Code спросит разрешение на сервер из `.mcp.json` при первом запуске.

## Агенты пространства

Агент — служебный участник пространства для Claude Code. Его создаёт владелец пространства в **Настройки → Агенты**:

- **название** («Claude — backend») и описание (репозиторий, зона ответственности);
- **ответственный** — участник-человек. Ему приходят уведомления, адресованные агенту: упоминание `@Claude — backend`, назначение ответственным, комментарии к задачам агента. В тексте уведомления — «(для агента …)». Если ответственный вышел из пространства, уведомления получают владельцы;
- **права** «Управление проектами» и «Управление документами» — как у обычного участника. Без «Управления документами» агент только читает документы.

Агент виден в списке участников с меткой «Агент», его можно назначить ответственным и упомянуть в комментарии. Войти в интерфейс агент не может: у него нет пароля и почты (служебный адрес `agent-<id>@agents.tasker.invalid`, письма на него не отправляются), сессию в браузере ему не выдаёт даже вход «под пользователем» из админки. В админке ресурса агентов нет — ими управляет владелец пространства. Пригласить служебный адрес агента нельзя.

На странице агента (`/w/<slug>/settings/agents/<id>`) владелец:

- выпускает и отзывает **токены агента** — отдельный токен на каждое место запуска (ноутбук, CI);
- смотрит **журнал действий** агента.

**Отключить** агента: все его токены отзываются, он перестаёт быть участником (с него снимаются задачи, его нельзя упомянуть). Задачи, комментарии и документы, которые он создал, остаются с его именем. **Включить** возвращает членство без дополнительных прав — права и токены нужно выдать заново. В пространстве до 20 включённых агентов.

## Токены доступа

| Свойство | Как работает |
|----------|--------------|
| Права | Права владельца токена (агента или пользователя) в **одном** пространстве, в пределах [областей](#области-токена) |
| Админка | Не даёт никогда: сессия токена всегда с ролью `user` |
| Хранение | В БД — только SHA-256 и начало токена (`tkr_abcd1234`) для списка. Сам токен показывается один раз |
| Срок | 30, 90 дней, год или бессрочно |
| Отзыв | **Отозвать** в списке — доступ пропадает сразу. Вернуть токен нельзя, только выпустить новый |
| Лимит | 20 действующих токенов на пользователя или агента |
| Блокировка и выход | Если пользователя заблокировали, он вышел из пространства или агента отключили, токен сразу перестаёт работать. Удаление пространства удаляет его токены |
| Последнее использование | Видно в списке, обновляется не чаще раза в минуту |

Храните токен как пароль: не коммитьте его и не вставляйте в задачи и PR.

### Области токена

Области задаются при выпуске и потом не меняются (нужны другие — выпустите новый токен):

| Область | Что разрешает |
|---------|---------------|
| Чтение (`read`) | Задачи, проекты, участники, документы, вложения — только чтение. Есть у любого токена |
| Задачи (`tasks`) | Создание и изменение задач, статусов, подзадач, комментариев и вложений, сценарии `start_task` и `finish_task` |
| Документы (`documents`) | Заметки, загрузка файлов, папки, теги, связи документов с задачами |

Инструменты вне областей агенту не показываются, а вызов такого инструмента отклоняется. Агент знает свои области: они перечислены в инструкциях сервера и в `get_workspace_context`. Область не заменяет права: для изменения документов нужны и область `documents`, и право «Управление документами» у владельца токена.

### Журнал действий

Каждое изменение через MCP записывается в журнал: когда, каким токеном и что сделано — «Перевёл TSK-42: К выполнению → В работе», «Создал заметку «ADR-7»». Чтение в журнал не попадает.

- Журнал агента — на странице агента, его видит владелец пространства.
- Журнал личного токена — ссылка **Журнал** у токена в профиле (`/profile/tokens/<id>`), его видит только владелец токена.

Записи хранятся 90 дней.

### Пометка «через агента»

Задача, комментарий и документ, созданные по **личному** токену, помечаются «через Claude Code» (в подсказке — название токена): в шапке комментария, в строке «создана» задачи и в мете документа. У созданного агентом пометки нет — автор и так агент. Остальные изменения (статус, правки, вложения) видны в журнале.

## Что умеет агент

### Инструменты

Задачи:

| Инструмент | Область | Что делает |
|------------|---------|------------|
| `get_workspace_context` | read | От чьего имени действует агент и его области, проекты со статусами, участники (агенты — с пометкой), правила документов и GitHub. Агент вызывает его первым |
| `list_tasks` | read | Поиск и фильтры: текст или ключ, проект, статус или категория (`todo`, `in_progress`, `done`, `none`), ответственный (`me`, `none`, email, имя), приоритет, срок, «только верхнего уровня», сортировка, страницы по 50 |
| `get_task` | read | Задача целиком: поля, статусы в проектах, цепочка родителей, подзадачи с прогрессом, PR (состояние, ревью, CI), ветки, коммиты, последние комментарии, связанные документы, рекомендованное имя ветки |
| `create_task` | tasks | Новая задача или подзадача (`parent`). Без `project` задача верхнего уровня встаёт в единственный проект пространства, если он один. Подзадача без `project` на доску не выводится — как в интерфейсе |
| `update_task` | tasks | Название, описание, приоритет, срок, ответственный. `null` очищает поле |
| `set_task_status` | tasks | Статус по названию, id или категории. Если задачи нет в проекте, она туда добавляется. `project` нужен, когда задача в нескольких проектах или ни в одном |
| `set_task_parent` | tasks | Сделать задачу подзадачей другой или вернуть на верхний уровень (`parent: null`). Циклы и вложенность глубже 10 уровней отклоняются |
| `add_comment` | tasks | Комментарий простым текстом. `@Имя` упоминает участника, и он получает уведомление. `attachmentIds` прикрепляет загруженные файлы, текст тогда можно не писать |
| `request_attachment_upload` | tasks | Шаг 1 прикрепления файла к задаче или комментарию (`target`): слот загрузки и готовая команда `curl` |
| `complete_attachment_upload` | tasks | Шаг 2: подтверждение после `curl`. Tasker проверяет, что файл есть, его размер и содержимое картинок |
| `get_attachment_url` | read | Ссылка на скачивание файла на 60 секунд — агент читает скриншоты и логи, которые прикрепили люди. id файлов показывает `get_task` |
| `get_github_conventions` | read | Правила привязки, подключённые репозитории и автосмена статуса по проектам |
| `preview_github_links` | read | Какие задачи привяжет имя ветки, сообщение коммита или текст PR. Тот же разбор, что у вебхука. С `repository` проверяет, что репозиторий подключён |

Документы:

| Инструмент | Область | Что делает |
|------------|---------|------------|
| `list_documents` | read | Документы папки (по умолчанию — корня) или поиск по всему пространству: `query`, `tag`, `kind` (`note`, `image`, `pdf`, `text`, `media`, `other`), страницы |
| `list_document_folders` | read | Дерево папок с id |
| `list_document_tags` | read | Теги пространства с id |
| `get_document` | read | Заметка — Markdown и `version`; текстовый файл (Markdown, CSV, JSON, код) — содержимое, до 100 КБ с пометкой об обрезке; остальные файлы — ссылка на скачивание на несколько минут. Плюс связанные задачи |
| `create_note` | documents | Заметка в папке, с существующими тегами и связями с задачами (`tasks: ["TSK-42"]`) |
| `update_note` | documents | Новое название и/или весь текст заметки. Нужна `version` из `get_document`: если заметку уже изменили, вызов отклоняется — агент перечитывает документ и применяет правку заново |
| `create_document_folder` | documents | Папка (в корне или в `parent`) |
| `set_document_tags` | documents | Заменить теги документа существующими (`[]` — снять все). Новые теги агент не создаёт |
| `link_document_to_task` / `unlink_document_from_task` | documents | Связать документ с задачей или убрать связь |
| `request_document_upload` / `complete_document_upload` | documents | Загрузка файла в «Документы» в два шага, как вложения |

Задачи указываются как `TSK-42`, `tsk-42`, `#42` или `42`, документы — id из `list_documents`, папки и теги — id, именем или путём папки («Specs / API»). Ключ другого пространства отклоняется с подсказкой правильного. Ошибки (нет прав, неизвестный статус, цикл подзадач, конфликт версии) приходят агенту текстом, и он может исправить вызов.

### Сценарии (промпты)

В Claude Code они доступны как слэш-команды (нужна область `tasks`):

| Команда | Что делает агент |
|---------|------------------|
| `/mcp__tasker__start_task TSK-42` | Читает задачу и связанные документы (или ищет документы по теме). Большую разбивает на подзадачи. Переводит задачу «в работу», если её не двинет автосмена. Создаёт ветку `tsk-42-…` и коммитит с `TSK-42:` |
| `/mcp__tasker__finish_task TSK-42` | Проверяет заголовок PR через `preview_github_links`, открывает PR `TSK-42: …`, оставляет комментарий-итог со ссылкой на PR, ставит статус по правилам автосмены. С областью `documents` — сохраняет решения и инструкции заметкой, связанной с задачей |

## Вложения и файлы документов

Файл не проходит через MCP: агент отправляет его прямо в хранилище Tasker по временной подписанной форме, как браузер.

1. `request_attachment_upload(task, fileName, size, target)` — имя файла с расширением, точный размер в байтах, `target`: `task` (по умолчанию) или `comment`. В ответе `attachmentId` и команда `curl` (синтаксис bash; на Windows — Git Bash или WSL). Слот живёт 5 минут.
2. Агент выполняет `curl` с путём к файлу. Хранилище отвечает `204`.
3. `complete_attachment_upload(task, attachmentId)`: файл в задаче. Для `target: comment` агент затем вызывает `add_comment` с `attachmentIds`. Неотправленный черновик виден только ему и удаляется через сутки.

Ограничения те же, что в интерфейсе: до 25 МБ, 20 файлов на задачу и 10 на комментарий, типы — по расширению (картинки, PDF, `txt`, `md`, `csv`, `json`, `zip`, офисные документы). Логи агент прикладывает как `.txt`. Картинка с чужим содержимым и файл не того размера отклоняются.

Файл в «Документы» загружается так же: `request_document_upload(fileName, size, folder?)` → `curl` → `complete_document_upload(documentId)`. Действуют ограничения раздела «Документы»: до 50 МБ на файл и квота хранилища пространства — при нехватке места агент получает понятную ошибку со свободным объёмом.

Хранилище должно быть доступно с машины агента. На проде оно открыто на том же домене (`/tasker-attachments`). Локально адрес задаёт `S3_PUBLIC_ENDPOINT` (по умолчанию `http://localhost:9000`).

## Как агент работает с GitHub

Правила те же, что в [Интеграции с GitHub](github.md#что-привязывается). Агент получает их тремя путями:

1. **При подключении:** в инструкциях MCP-сервера — коротко.
2. **Через `get_github_conventions` и `get_workspace_context`:** полностью, с подключёнными репозиториями и автосменой статуса.
3. **Через `preview_github_links`:** проверка конкретной ветки или PR перед `git push` и `gh pr create`.

Главное:

- Одна задача — одна ветка: `tsk-42-short-slug`. Рекомендованное имя отдаёт `get_task`.
- Каждый коммит начинается с `TSK-42:`, заголовок PR — `TSK-42: …`.
- В PR **не упоминаются ключи других задач**, даже родительской: каждый ключ привязывает PR к своей задаче.
- У подзадачи свой ключ, работа над ней идёт в ветке с её ключом.
- Если в проекте настроена автосмена статуса по PR, агент не двигает статус вручную на этих шагах. Иначе ставит `in_progress` при старте и `done` после слияния.
- Если репозиторий не выбран в настройках GitHub пространства, привязки не будет, и агент сообщает об этом пользователю.

## Ограничения

- Агент не удаляет задачи, вложения, документы и папки, не переименовывает и не переносит документы, не создаёт теги.
- История изменений полей в Tasker не ведётся: что агент поменял, видно в журнале действий, а пометка «через Claude Code» — только у созданного.
- Области токена задаются при выпуске и не меняются.
- Частота запросов по токену не ограничивается.
- Авторизация MCP — только bearer-токен, без OAuth.

## Частые проблемы

| Симптом | Причина |
|---------|---------|
| `/mcp` показывает `failed` или `needs authentication` | Токен неверный, отозван или истёк, пользователь заблокирован или вышел из пространства, агент отключён. Выпустите новый токен и переподключите сервер |
| В `.mcp.json` сервер не подключается | Переменная `TASKER_TOKEN` не задана в окружении, где запущен Claude Code |
| Агент «не видит» `create_task` или `create_note` | У токена нет области `tasks` или `documents`. Выпустите токен с нужной областью |
| «Недостаточно прав для управления документами» | У агента (или владельца личного токена) нет права «Управление документами». Владелец пространства выдаёт его в **Агенты → Изменить** или в списке участников |
| «Документ изменили после вашего чтения…» в `update_note` | Заметку изменили после `get_document`. Агент перечитывает её и применяет правку к новой `version` |
| «В хранилище пространства не хватает места» | Квота «Документов» исчерпана. Удалите ненужные файлы или увеличьте квоту (`DOCUMENTS_WORKSPACE_QUOTA_MB`) |
| «Задача ABC-1 не из этого пространства» | Токен выпущен для другого пространства: у каждого пространства свой ключ |
| «Укажите project» в `set_task_status` | Задача в нескольких проектах или ни в одном (частый случай для подзадач) |
| PR не привязался к задаче | Ключ не на границе слова или с ведущим нулём, репозиторий не выбран в пространстве, GitHub App не создан. Проверьте текст через `preview_github_links` с `repository` |
| PR привязался к лишней задаче | В заголовке или описании PR есть её ключ. Уберите его и сохраните PR: связи пересчитаются |
| «Такой тип файла нельзя прикрепить» | Расширения нет в списке разрешённых. Логи и прочий текст — `.txt` |
| `curl` вернул `403`, потом «Файл не загрузился» | Слот истёк (5 минут) или размер не совпал с `size`. Запросите новый слот с точным размером |
| `curl` не может подключиться к хранилищу | Адрес хранилища (`S3_PUBLIC_ENDPOINT`) недоступен с машины агента |
| Уведомления агенту никто не получает | У агента нет ответственного, и в пространстве нет владельцев-людей. Назначьте ответственного в **Агенты → Изменить** |
