## Задачи: Tasker

Задачи этого репозитория ведутся в Tasker. Работай с ними через MCP-сервер `tasker`, а не через TODO-файлы.

- В начале сессии вызови `get_workspace_context`: проекты, статусы, участники и правила привязки к GitHub.
- Начинай задачу с `/mcp__tasker__start_task <KEY>`, заканчивай — `/mcp__tasker__finish_task <KEY>`.
- Ключ задачи (`TSK-42`) обязателен:
  - в имени ветки — `tsk-42-short-slug` (рекомендованное имя отдаёт `get_task`);
  - в начале каждого сообщения коммита — `TSK-42: что сделано`;
  - в заголовке PR — `TSK-42: …`.
- В заголовке и описании PR не упоминай ключи других задач, даже родительской: каждый ключ привязывает PR к своей задаче. Перед `git push` и `gh pr create` проверь текст через `preview_github_links`.
- Одна задача — одна ветка. Большую задачу разбей на подзадачи (`create_task` с `parent`) и веди каждую в своей ветке с её ключом.
- Статусы: если в проекте настроена автосмена по PR (`get_github_conventions`), не двигай статус вручную. Иначе ставь `in_progress` при старте и `done` после слияния.
- Существенные решения, блокеры и итог работы со ссылкой на PR записывай комментарием (`add_comment`). Участников упоминай как `@Имя`.
- Логи, скриншоты и отчёты прикладывай к задаче или комментарию: `request_attachment_upload` → `curl` → `complete_attachment_upload` (логи — как `.txt`). Файлы, которые прикрепили люди, читай через `get_attachment_url`.
- Новую работу, найденную по ходу, заводи задачей (`create_task`), а не держи в голове.
- Спецификации, ADR и инструкции лежат в разделе «Документы» Tasker. Перед работой прочитай документы, связанные с задачей (`get_task` перечисляет их, `get_document` читает), и поищи по теме (`list_documents`).
- Решения и инструкции, которые стоит сохранить (ADR, отчёт, заметки по реализации), записывай заметкой (`create_note` с `tasks: ["TSK-42"]`). Правь заметку только через `update_note` с актуальной `version` из `get_document`.
